# Define Pretty

将参考 UI 截图转换为分三级的视觉规范卡片，包含定位、局部裁切、布局比例图、配色表及字体和空间参数表。用户选择喜欢的设计，调整应用要求，再将卡片图、无标记原图和配套指令交给 AI。

## 使用流程

1. 上传 PNG、JPEG 或 WebP 参考图。
2. 默认生成一级基础规范与二级辨识特征。一级固定四张：「整体视觉风格」「字体与文字层级」「布局与空间关系」「配色与明暗分配」；二级根据参考图提取硬边框、偏移阴影、插画等有依据的辨识特征，不凑数量。第三级精细细节默认不生成，点击「发现更多细节」会新建版本并保留原有卡片、参数与勾选；新增细节默认未选中。旧板可继续编辑和使用，通过「重新提炼基础与辨识特征」获得新版规范，原结果保留。
3. 一级的字体表列明字体或候选、字号、字重、行高、字距、相对正文比例及参考宽度；配色表包含 HEX 色板、颜色角色、用途、面积占比，区分页面背景、内容表面与外部展示背景；空间表列明数值、单位、计算基准与范围。参数逐项区分「图中明示」「观察估计」「迁移建议」，不能把建议字体当成原图识别结果。二级用属性表说明具体做法与作用范围。可在卡片编辑器修改参数，图表、PNG 和配套指令共用同一份数据。
   布局卡继续使用比例色块：分栏按所属区域扣除间距后的可用长度分配，叠放按主窗口的宽、高及偏移计算，嵌套内容区随外层尺寸更新。勾选即认可结构，无需额外选择布局。色块颜色仅表示角色，真实配色由选中的配色卡规定。旧图没有比例约束时显示原几何推算的画布占比，可用 AI 补全更新。
4. 每张卡片说明「带来什么效果」「怎么实现」「适合用在哪里」。点击「AI 补全」会生成对应类别的规则及参数草稿，检查后保存；不自动覆盖原卡片。四张基础卡可取消勾选，不能删除或改变分类。
5. 勾选需要借鉴的卡片，填写应用区域或交给模型建议。必须固定的参数也可写在应用要求中；勾选或保存卡片不会自动锁定所有估计值。
6. 预览并下载卡片 PNG 和无标记原图，复制配套指令，将两张图片与指令一起交给 AI。卡片图只包含勾选的卡片与参数；原图按原始文件提供，不缩放或重新压缩，仅补充已选特征的视觉细节。三级分类用于组织与检查；用户明确要求优先，观察估计和迁移建议可根据原图与实际渲染校准。未选规范不会成为实施要求。
7. 点击底部「原始网页」标题旁的「更换网页」，在弹窗中选择 8 款可直接使用的网页：Dashboard、个人简历、个人博客、SaaS 官网、设计师作品集、电商、在线课程和活动报名。场景列表默认隐藏；点击缩略图可全屏预览，点击「使用此页」立即替换原网页并关闭弹窗，作为下一次测试的起点，无需先调用模型生成。也可在弹窗中的「我的原网页」选择已生成或历史网页，或在同一弹窗中展开「自定义原始网页」，填写需求并设置生成模型。原网页生成只接收需求，不接收参考图或卡片；成功后自动选择该网页作为测试起点。关闭弹窗后生成继续，可从「查看生成进度」重新打开并取消任务。需求草稿与选择在浏览器保留，生成历史和冻结副本保存在本地服务；失败、取消或中断不会替换已有网页。
8. 可点击「测试所选设计」，将实际导出的卡片图、无标记原图和指令发送给 Codex，从同一份冻结的原网页直接生成最终修改结果，在底部左右对比。两张输入图片与原图哈希随本次测试保存，可在「查看本次实际输入图片与完整指令」中核对。勾选布局卡片即授权在所填应用范围内按该卡片的结构关系重新组织布局，保留真实业务内容、数据与交互，允许重组 HTML 容器、栏数、区块顺序和卡片边界。无需再选择布局方案；未选布局卡片时，不因整体风格、配色或字体等卡片主动重排整页。
9. 结果有可预览产物时，可填写具体差距并点击「继续优化此结果」。它复制这一轮的网页，在同一组冻结卡片和参考输入下继续修改，生成独立历史记录；不会覆盖上一轮，也不重新从原网页生成。当前编辑区的卡片变化不会带入继续优化，需要改选特征时使用「测试所选设计」。失败但已保留网页的任务也可继续。每轮记录父产物哈希和本轮反馈，并继承此前优化要求；有明确变更时以最新反馈为准。左侧仍展示最初冻结的原网页。

模型可自行组合 HTML/CSS、Canvas、SVG、本地素材及图片生成或编辑工具。插画、照片、材质等适合生图时可以直接调用，无需先尝试代码绘制；也不要求所有视觉元素都生图。生图复用当前 Codex CLI 与 provider，功能开关开启不代表调用已成功，需要真实生成并检查落盘与预览。能力不可用或调用失败时，应记录原因及采用的替代方法，不自动切换账号或 provider。测试结果与原网页生成历史中的「实施说明」保留模型报告，可查看工具失败、替代方案和未验证项。

实施指令提供冻结参考图的本地路径，支持将原图或局部像素实际传入图像生成/编辑工具。视觉检查要求打开渲染截图，比较已选特征的构图、造型、字形占幅、材质及细节密度；不把尺寸正确、加载无错误或通用占位图视为还原完成。卡片参数仍为可校准起点，不新增固定实现方法或迭代轮数。

卡片生成、手动补全使用生成设置；验证修改可单独配置模型和推理强度。任务支持取消，超时为 30 分钟，服务重启后保留中断记录。测试重跑产生新记录，不覆盖之前的结果。所有网页预览采用 1440 × 1000 内部视口，支持浏览器内全屏查看。

网页完成状态表示通过现有加载检查，实际视觉与交互效果仍需在对比预览中查看。

## 本地运行

需要 Node.js、已安装并登录的 Codex CLI，以及供图片裁切和网页验证使用的 Chrome、Edge 或 Chromium。

```sh
npm install
npm run dev
```

生产构建与启动：

```sh
npm run build
npm start
```

默认控制台：http://127.0.0.1:4193/ 。静态网页预览使用 4194 端口。原有 `dev:cards`、`build:cards`、`start:cards` 命令保留为别名。

`npm run dev` 的前端由 Vite 热更新，后端不会自动重启。修改 `server/` 或后端引用的 `shared/` 后，应等待在途任务结束，再停止并重新启动服务；只刷新浏览器不会让新的执行配置和提示词生效。

### 内置原始网页

从控制台顶部「原始网页」进入，或打开 http://127.0.0.1:4193/#original-websites ，再点击原网页预览标题旁的「更换网页」打开场景选择弹窗。新安装默认使用 Dashboard；已有网页选择会保留。

| 场景 | 风格 | 可测试的内容与交互 |
| --- | --- | --- |
| 数据 Dashboard | 深色霓虹 | 指标、图表、表格筛选和待办 |
| 个人简历 | 经典渐变 | 经历时间线、技能与项目展示 |
| 个人博客 | 经典渐变 | 分类、搜索与文章阅读 |
| SaaS 产品官网 | 经典渐变 | 功能、定价、FAQ 与产品体验 |
| 设计师作品集 | 深色霓虹 | 作品筛选与项目详情 |
| 电商商品页 | 经典渐变 | 商品浏览、购物车数量和金额 |
| 在线课程 | 经典渐变 | 课程筛选、课程详情与学习进度 |
| 活动报名 | 深色霓虹 | 议程切换与本地报名表单 |

网页刻意保留早期 AI 常见的蓝紫渐变、Emoji、重复卡片、圆角和阴影，便于观察设计优化。所有品牌、人物、数据、价格均为演示内容，交互在本地完成。源文件在 `public/builtin-websites/<场景>/index.html`，每款独立、无外部依赖。

启动时按内容哈希创建冻结副本，后续测试只修改独立测试副本。内置文件更新后产生新的来源版本，历史对比仍引用原有副本。生产模式修改页面后需重新构建并重启服务。

### 最初的风格候选

打开 http://127.0.0.1:4193/ai-baselines/ 可对比四版早期 AI 风格的 FlowAI 演示网页：A 经典整块渐变、B 白底通用模板、C 深色霓虹科技、D 满屏玻璃拟态。首屏统一为 1440 × 1000，完整预览支持桌面和手机尺寸；「记为候选」只保存在浏览器，不会替换验证工作台的默认原网页。

源文件位于 `public/ai-baselines/`，各候选为无外部依赖的独立 HTML，包含页内导航、定价和本地演示表单。生产模式下新增或修改候选后需运行 `npm run build`。

```sh
npm run check
npm test
```

## 配置

| 环境变量 | 默认值 | 用途 |
| --- | --- | --- |
| `DEFINE_PRETTY_PORT` | `4193` | 控制台端口 |
| `DEFINE_PRETTY_PREVIEW_PORT` | `4194` | 独立静态预览端口 |
| `DEFINE_PRETTY_DATA_DIR` | `.data/visual-cards` | 卡片、图片与验证记录 |
| `DEFINE_PRETTY_DIST_DIR` | `dist/visual-cards` | 生产构建目录 |
| `DEFINE_PRETTY_SOURCE_DATA_DIR` | `.data` | 首次导入验证原网页时只读访问的历史数据目录 |
| `DEFINE_PRETTY_CHROME` | 自动查找 | 浏览器可执行文件路径 |

模型、provider 和 CLI 版本从本机 Codex 配置读取，复用现有登录。CLI 通过参数数组和 stdin 调用；卡片分析以只读沙箱运行，可使用只读图像分析命令与可用工具，保持原始输入不变。生成和修改网页以独立工作目录运行，并开启工作目录沙箱的网络访问；生成期间可以下载素材、安装依赖、构建和启动临时预览，也可截图对照参考图并自主修正。

网页任务会获得 `node preview.mjs` 截图入口，可指定视口宽高，返回当前 `website/` 的实际渲染及加载诊断。浏览器由本地服务启动，避免 macOS 工作目录沙箱阻止 Chrome 启动；页面仍使用与最终预览相同的隔离策略。入口只接受本任务的静态文件，不提供任意网址导航或浏览器控制权限，任务结束、取消或超时后关闭。模型自主决定何时截图、如何修改，不设固定迭代轮数。普通 SVG 图片可加载；SVG sprite 应使用同文档 `symbol`，外链 `<use>` 会受到浏览器同源限制。

最终交付仍为可直接预览的 `website/index.html` 及本地静态资源。生成图片和下载素材保存到 `website/assets/`，构建源文件与依赖留在 `website/` 之外。生成阶段联网不改变成品的预览隔离策略。

## 数据与兼容

- 图片文件保留在 `references/`；图片索引使用 `references.json`。首次读取可兼容原 `store.json` 中的图片索引；新上传不会改写历史实验记录。
- 卡片、补全任务、验证任务分别保存在 `feature-boards/`、`feature-completions/`、`feature-tests/`。目录中的输入、配置、日志和运行结果用于追溯。新测试额外冻结无标记原图，记录文件名、类型及哈希；旧测试记录继续读取，只展示当时实际传入的卡片图。
- 内置网页启动时冻结到 `feature-tests/sources/`；新安装无需历史数据即可选择网页并进行验证。原有 `feature-tests/source.json` 及已冻结副本继续保留；未导入时仍可从历史数据最后一个实验读取已完成的原网页并校验哈希。历史来源、已生成网页与内置网页可以并存，尚未提供上传应用的入口。
- 旧多组实验界面、分组规范生成、调度器、评价与变化高亮接口已移除。`?view=experiments` 现在也显示卡片工作台；旧 `/api/experiments`、`/api/runs` 等接口返回 404。
- 磁盘中的历史实验和运行产物保留，不清理、不迁移其状态；旧实现可从 Git 历史恢复。
- `.data/`、`dist/` 与依赖不纳入 Git。数据目录使用进程锁，防止多个服务同时修改。

控制台写入接口校验来源和会话令牌；生成网页仅在另一个端口提供静态文件，并以限制权限的 iframe 运行。预览不能访问执行接口，文件读取拒绝路径穿越与符号链接。

网页验证允许通过 HTTPS 加载远程字体文件及字体样式表（如字体服务的 CSS），其他外部脚本、图片与业务请求仍受预览策略限制；生成期间获取并保存到交付目录的图片可正常预览。检查会等待字体加载并记录请求失败、字体错误或超时；加载成功不等于视觉还原完成，也不能保证所有汉字都使用了预期字体。远程资源不可用时，浏览器可能显示回退字体。
