# Define Pretty

将参考 UI 截图转换为可勾选的视觉总览。参考图居中，基础规范、辨识特征与精细细节在四周紧凑分布，通过局部示例、布局比例、色板和关键参数帮助用户判断要采纳哪些设计。工作台与导出 PNG 共用摘要和排版规则，完整实施细节保留在配套指令与编辑器中。用户选择喜欢的设计，调整应用要求，再将总览图、无标记原图和配套指令交给 AI。参考图提供精确的风格依据，目标网站的内容与用途决定素材主题、叙事和表达，生成适合当前网站的新素材。

## 快速启动

需要 **Node.js 22.12 或更新版本**（含 npm / npx）。从本仓库的 GitHub Releases 下载 `define-pretty.tgz`，在文件所在目录执行：

```sh
npx --yes --package ./define-pretty.tgz define-pretty
```

发布说明也会提供直接使用 Release 下载地址的一条命令，无需手动下载、克隆源码或构建。发布包包含完整前后端、8 款内置网页和使用指引；运行时不会安装开发工具。

启动后自动打开浏览器。默认从 `http://127.0.0.1:4193/` 打开工作台，预览使用独立端口；端口被占用时自动选择其他可用端口，以终端输出为准。保持终端运行，按 **Ctrl+C** 停止任务并保存记录。

未安装或未登录 Codex 时，也可以先体验内置使用指引。真实提炼、补全和网页生成需要[安装 Codex CLI](https://developers.openai.com/codex/cli/)并运行 `codex login`；程序沿用本机配置和登录，不代为安装 Codex 或修改账号。安装或登录后重启工作台。

截图、图片裁切和网页验证自动查找 Chrome、Edge 或已安装的 Chromium。缺少浏览器时，可使用同一个启动命令加 `--install-browser` 下载与当前包匹配的 Chromium：

```sh
npx --yes --package ./define-pretty.tgz define-pretty --install-browser
```

常用选项：

| 选项 | 用途 |
| --- | --- |
| `--no-open` | 仅启动，不自动打开浏览器 |
| `--doctor` | 检查 Codex、登录、模型列表和截图浏览器后退出；检查失败返回非零退出码 |
| `--port 4301 --preview-port 4302` | 使用固定端口；占用时明确报错 |
| `--data-dir /path/to/data` | 指定图片、卡片、任务历史的数据目录 |
| `--help` | 查看全部选项 |

选项放在启动命令的 `define-pretty` 后面，例如 `npx --yes --package ./define-pretty.tgz define-pretty --doctor`。

正式启动使用固定的用户数据目录，与当前目录、npx 缓存和安装版本无关：

| 系统 | 默认数据目录 |
| --- | --- |
| macOS | `~/Library/Application Support/Define Pretty` |
| Linux | `${XDG_DATA_HOME:-~/.local/share}/define-pretty` |
| Windows | `%LOCALAPPDATA%\Define Pretty` |

更换版本或删除 npx 缓存不会删除历史。相同数据目录只允许一个实例；重复启动会提示已有实例，避免中断运行中的任务。模型调用仍需联网。

## 首次使用指引

首次打开会自动开始快速体验，也可以从页头「使用指引」重新体验。示例带你走过上传入口、提炼、选择、网页验证和导出；无需上传、登录 Codex 或等待模型生成。下载、复制均可跳过；任意步骤按 Escape 或点击「跳过」退出，恢复原工作区。正在执行任务或打开编辑弹窗时，指引暂不启动。

演示资源随项目保存在 `resources/onboarding/v1/`，包括参考图、8 张卡片和博客优化前后的完整网页，不依赖本机历史数据。来源为已完成的测试 `8d0f8d29-a106-4adf-be1f-08575b1b0271`；演示勾选仅保存在内存，不产生真实任务。正式新提炼的完整卡片默认全选，追加细节仍默认不选，已有勾选保留。浏览器按站点记住已完成或跳过的指引版本。

`npm run test:onboarding -- http://127.0.0.1:4293` 可对运行中的隔离开发服务执行只读浏览器回归，覆盖未登录体验、逐步退出恢复、导出、剪贴板降级和窄屏布局；截图与检查结果写入 `.test-data/onboarding-qa/`。使用 4293/4294 端口及独立数据目录启动该服务，避免影响日常任务。

## 使用流程

1. 上传 PNG、JPEG 或 WebP 参考图。
2. 默认生成一级基础规范与二级辨识特征。一级固定四张：「整体视觉风格」「字体与文字层级」「布局与空间关系」「配色与明暗分配」；二级根据参考图提取硬边框、偏移阴影、插画等有依据的辨识特征，不凑数量。第三级精细细节默认不生成，点击「发现更多细节」会新建版本并保留原有卡片、参数与勾选；新增细节默认未选中。旧板可继续编辑和使用，通过「重新提炼基础与辨识特征」获得新版规范，原结果保留。
3. 总览默认只展示视觉示例与关键参数：字体最多五个层级，布局展示比例图与前四项空间参数，色板展示页面使用的颜色，辨识特征展示局部裁切与前三项属性。未展示的参数仍完整保留。完整字体表列明字体或候选、字号、字重、行高、字距、相对正文比例及参考宽度；配色表包含 HEX 色板、颜色角色、用途、面积占比，区分页面背景、内容表面与外部展示背景；空间表列明数值、单位、计算基准与范围。参数逐项区分「图中明示」「观察估计」「迁移建议」，不能把建议字体当成原图识别结果。可在「编辑要求」中展开完整规则和参数进行修改；总览、PNG 和配套指令读取同一份数据，无需额外模型摘要。
   布局卡继续使用比例色块：分栏按所属区域扣除间距后的可用长度分配，叠放按主窗口的宽、高及偏移计算，嵌套内容区随外层尺寸更新。勾选即认可结构，无需额外选择布局。色块颜色仅表示角色，真实配色由选中的配色卡规定。旧图没有比例约束时显示原几何推算的画布占比，可用 AI 补全更新。
4. 从总览直接勾选要采纳的特征，悬停或聚焦可查看参考图中的出处，也可放大查看原图。「带来什么效果」「怎么实现」「适合用在哪里」等完整内容在编辑器及配套指令中查看；日常选择无需逐项阅读实施细节。点击「AI 补全」会生成对应类别的规则及参数草稿，检查后保存；不自动覆盖原卡片。四张基础卡可取消勾选，不能删除或改变分类。
5. 勾选需要借鉴的卡片，填写应用区域或交给模型建议。必须固定的参数也可写在应用要求中；勾选或保存卡片不会自动锁定所有估计值。
6. 预览并下载总览 PNG 和无标记原图，复制配套指令，将两张图片与指令一起交给 AI。总览图覆盖全部已选特征，只展示其视觉摘要和关键参数，编号与完整配套指令一致；原图按原始文件提供，不缩放或重新压缩，仅补充已选特征的风格细节，素材内容围绕目标网站创作。三级分类用于组织与检查；用户明确要求优先，观察估计和迁移建议可根据原图与实际渲染校准。未选规范不会成为实施要求。历史测试与继续优化保留当时实际使用的图片，不随新总览样式重新生成。
7. 点击底部「原始网页」标题旁的「更换网页」，在弹窗中选择 8 款可直接使用的网页：Dashboard、个人简历、个人博客、SaaS 官网、设计师作品集、电商、在线课程和活动报名。场景列表默认隐藏；点击缩略图可全屏预览，点击「使用此页」立即替换原网页并关闭弹窗，作为下一次测试的起点，无需先调用模型生成。也可在弹窗中的「我的原网页」选择已生成或历史网页，或在同一弹窗中展开「自定义原始网页」，填写需求并设置生成模型。原网页生成只接收需求，不接收参考图或卡片；成功后自动选择该网页作为测试起点。关闭弹窗后生成继续，可从「查看生成进度」重新打开并取消任务。需求草稿与选择在浏览器保留，生成历史和冻结副本保存在本地服务；失败、取消或中断不会替换已有网页。
8. 可点击「测试所选设计」，将实际导出的卡片图、无标记原图和指令发送给 Codex，从同一份冻结的原网页直接生成最终修改结果，在底部左右对比。两张输入图片与原图哈希随本次测试保存，可在「查看本次实际输入图片与完整指令」中核对。勾选布局卡片即授权在所填应用范围内按该卡片的结构关系重新组织布局，保留真实业务内容、数据与交互，允许重组 HTML 容器、栏数、区块顺序和卡片边界。无需再选择布局方案；未选布局卡片时，不因整体风格、配色或字体等卡片主动重排整页。
9. 结果有可预览产物时，可填写具体差距并点击「继续优化此结果」。它复制这一轮的网页，在同一组冻结卡片和参考输入下继续修改，生成独立历史记录；不会覆盖上一轮，也不重新从原网页生成。当前编辑区的卡片变化不会带入继续优化，需要改选特征时使用「测试所选设计」。失败但已保留网页的任务也可继续。每轮记录父产物哈希和本轮反馈，并继承此前优化要求；有明确变更时以最新反馈为准。左侧仍展示最初冻结的原网页。

模型可自行组合 HTML/CSS、Canvas、SVG、本地素材及图片生成或编辑工具。插画、照片、材质等适合生图时可以直接调用，无需先尝试代码绘制；也不要求所有视觉元素都生图。生图复用当前 Codex CLI 与 provider，功能开关开启不代表调用已成功，需要真实生成并检查落盘与预览。能力不可用或调用失败时，应记录原因及采用的替代方法，不自动切换账号或 provider，也不退回参考图裁片。测试结果与原网页生成历史中的「实施说明」保留模型报告，逐项说明主要素材的文件、用途、来源和实际制作方式，可查看工具失败、替代方案和未验证项。

网页生成和继续优化允许最多 3 个子代理并行处理独立工作，例如素材、字体准备和局部组件；主代理负责文件分工、合并与整体检查，并向素材子代理同步目标用途、风格依据和禁止照搬的要求。并行能力按网页任务启用，不修改本机全局配置。任务会核实已有素材的来源与用途，复用适用的业务素材和独立创作素材；本轮修改范围内继承的参考图裁片需替换，即使题材与业务相关，并从交付副本移除已不用的裁片，用户明确要求复用的具体素材除外。任务分批保存代码、尽早提供可渲染版本；后续检查针对尚未解决的具体问题，避免重复准备与无依据的返工。

生成中会显示实际耗时、最近活动、执行步骤与子代理状态，不估算完成百分比。首次运行截图检查后，可查看「阶段预览」，之后用「查看更新」刷新，轮询不会反复重载页面。阶段预览展示仍可变化的当前草稿，不代表完成验收；取消或中断后保留有效草稿，但失败的原网页不会自动成为可选来源。旧记录没有活动日志时仍可查看历史结果。

实施指令提供冻结参考图的本地路径，支持将原图或局部像素作为风格参考传入图像生成/编辑工具，同时明确目标网站所需的素材内容。原图及裁片可用于风格分析、取色、测量、卡片示例或生图参考；未经用户明确要求复用，不得直接成为成品中的人物、物体、装饰、背景或纹理，抠图、换色和缩放也不算重新创作。用于分析的裁片留在交付目录之外，卡片中的局部示例继续保留。视觉检查要求打开渲染截图，比较已选特征的线条节奏、形状语言、色彩与明暗关系、字形占幅、材质及细节密度，并检查素材是否表达当前网站的业务主题、适合所在模块。参考图中的具体人物、物体、姿态与场景是观察样本，仅在用户明确要求时保留。风格一致性、素材完成度与业务适配共同决定效果，尺寸正确、加载无错误或通用占位图不足以通过视觉检查。卡片参数仍为可校准起点，不新增固定实现方法或迭代轮数。

卡片生成、手动补全使用生成设置，默认推理强度为 `high`，已保存的有效选择继续沿用；验证修改可单独配置模型和推理强度。两组设置共用本机 Codex CLI 返回的可选模型列表，推理强度随所选模型联动；原网页生成与测试共用同一组设置。服务启动时读取模型列表，更新本机 CLI 或登录后重启服务即可重新读取；读取失败时显示原因并保留手动填写。任务支持取消，超时为 30 分钟，服务重启后保留中断记录。测试重跑产生新记录，不覆盖之前的结果。所有网页预览采用 1440 × 1000 内部视口，支持浏览器内全屏查看。

网页完成状态表示通过现有加载检查，实际视觉与交互效果仍需在对比预览中查看。

## 源码开发

需要 Node.js >= 22.12。在源码目录安装开发依赖并启动：

```sh
npm ci
npm run dev
```

生产构建与启动：

```sh
npm run build
npm start
```

`npm run dev` 保持使用仓库内 `.data/visual-cards` 和 Vite 热更新；不自动打开浏览器。`npm start` 使用已构建的发布入口、自动打开浏览器，并使用上面的固定用户数据目录。原有 `dev:cards`、`build:cards`、`start:cards` 命令保留为别名。

如果希望生产入口继续使用当前仓库的旧数据，显式指定目录，无需复制或迁移：

```sh
npm start -- --data-dir .data/visual-cards --source-data-dir .data
```

`npm run dev` 的前端由 Vite 热更新，后端不会自动重启。修改 `server/` 或后端引用的 `shared/` 后，应等待在途任务结束，再停止并重新启动服务；只刷新浏览器不会让新的执行配置和提示词生效。生产入口需先重新构建。

### 运行核心

`server/core.ts` 负责服务生命周期、数据锁和任务管理；`server/cli.ts` 负责参数、环境检查、浏览器打开和退出信号。导入核心不会启动服务或注册全局信号处理。安装发布包后可以在自己的 Node.js 程序中调用：

```js
import { startLocalService } from 'define-pretty/core';

const service = await startLocalService({ dataDirectory: '/absolute/path/to/data' });
console.log(service.consoleOrigin, service.previewOrigin);
// 宿主在退出时调用；会取消在途任务并保留中断记录。
await service.shutdown();
```

核心仅监听 `127.0.0.1`，没有公网绑定选项。界面、示例和内置网页相对安装位置加载，不依赖调用者的工作目录；数据路径由宿主明确传入。

### 打包与 GitHub 发布

```sh
npm run pack:release
```

生成 `.release/define-pretty.tgz` 和 `.release/SHA256SUMS`。打包前自动类型检查并构建；白名单只包含发布代码、前端与必要资源，排除本地数据、日志、测试和开发依赖。也支持标准 `npm pack`，会通过 `prepack` 自动构建。

在本机直接验证这个发布包：

```sh
npx --yes --package ./.release/define-pretty.tgz define-pretty
```

将 `define-pretty.tgz` 和 `SHA256SUMS` 上传到 GitHub Release 后，用户可以一条命令下载并启动。以下 `OWNER/REPO` 替换为真实仓库名；无需 npm 账号或 npm registry 发布：

```sh
npx --yes --package=https://github.com/OWNER/REPO/releases/latest/download/define-pretty.tgz define-pretty
```

`.github/workflows/release.yml` 在推送、PR 和手动触发时执行 macOS / Linux 验证；推送与 `package.json` 版本一致的标签（如 `v0.1.0`）时，测试通过后创建带安装命令的 **GitHub Release 草稿**。维护者检查草稿后发布。手动触发仅构建并上传工作流产物。

```sh
npm test
npm run test:package
```

`test:package` 重新打包，从仓库之外通过 npx 与仅含生产依赖的安装环境验证启动、类型声明、示例资源、重复启动保护、上传持久化和退出清理；使用隔离数据与模拟 Codex，不发起真实生成。设置 `DEFINE_PRETTY_PACKAGE_BROWSER_TEST=1` 会额外检查发布包中的真实浏览器界面。当前发布流程验证 macOS 和 Linux；Windows 路径与启动适配尚未经过同等端到端验证。

启动时按内容哈希创建冻结副本，后续测试只修改独立测试副本。内置文件更新后产生新的来源版本，历史对比仍引用原有副本。生产模式修改页面后需重新构建并重启服务。

## 配置

| 环境变量 | 默认值 | 用途 |
| --- | --- | --- |
| `DEFINE_PRETTY_PORT` | 从 `4193` 查找可用端口 | 固定控制台端口；被占用时报错 |
| `DEFINE_PRETTY_PREVIEW_PORT` | 从 `4194` 查找可用端口 | 固定独立静态预览端口；被占用时报错 |
| `DEFINE_PRETTY_DATA_DIR` | 正式入口为用户数据目录；开发为仓库 `.data/visual-cards` | 卡片、图片与验证记录 |
| `DEFINE_PRETTY_DIST_DIR` | 发布包内 `dist/visual-cards` | 覆盖已构建前端目录 |
| `DEFINE_PRETTY_SOURCE_DATA_DIR` | 正式入口与数据目录相同；开发为仓库 `.data` | 首次导入旧实验原网页时只读访问的目录 |
| `DEFINE_PRETTY_CHROME` | 自动查找 | 浏览器可执行文件路径 |

CLI 参数优先于对应环境变量；只有明确指定的相对路径才相对当前工作目录解析。

模型、provider 和 CLI 版本从本机 Codex 配置读取，复用现有登录。CLI 通过参数数组和 stdin 调用；卡片分析以只读沙箱运行，可使用只读图像分析命令与可用工具，保持原始输入不变。生成和修改网页以独立工作目录运行，并开启工作目录沙箱的网络访问；生成期间可以下载素材、安装依赖、构建和启动临时预览，也可截图对照参考图并自主修正。

网页任务会获得 `node preview.mjs` 截图入口，可指定视口宽高，返回当前 `website/` 的实际渲染及加载诊断。浏览器由本地服务启动，避免 macOS 工作目录沙箱阻止 Chrome 启动；页面仍使用与最终预览相同的隔离策略。入口只接受本任务的静态文件，不提供任意网址导航或浏览器控制权限，任务结束、取消或超时后关闭。模型自主决定何时截图、如何修改，不设固定迭代轮数。普通 SVG 图片可加载；SVG sprite 应使用同文档 `symbol`，外链 `<use>` 会受到浏览器同源限制。

截图会在浏览器内触发离屏图片加载，以共享的有界等待窗口检查图片，避免把尚未触发的懒加载误报为丢图；交付 HTML 保持不变。执行进度写入 `work/progress.json`，截图检查点写入 `work/draft-preview.json`，均通过原子写入供轮询读取；界面只接收活动摘要，不展示内部推理和原始命令载荷。

最终交付仍为可直接预览的 `website/index.html` 及本地静态资源。生成图片和下载素材保存到 `website/assets/`，构建源文件与依赖留在 `website/` 之外。生成阶段联网不改变成品的预览隔离策略。

## 数据与兼容

- 图片文件保留在 `references/`；图片索引使用 `references.json`。首次读取可兼容原 `store.json` 中的图片索引；新上传不会改写历史实验记录。
- 卡片、补全任务、验证任务分别保存在 `feature-boards/`、`feature-completions/`、`feature-tests/`。目录中的输入、配置、日志和运行结果用于追溯。新测试额外冻结无标记原图，记录文件名、类型及哈希；旧测试记录继续读取，只展示当时实际传入的卡片图。
- 内置网页启动时冻结到 `feature-tests/sources/`；新安装无需历史数据即可选择网页并进行验证。原有 `feature-tests/source.json` 及已冻结副本继续保留；未导入时仍可从历史数据最后一个实验读取已完成的原网页并校验哈希。历史来源、已生成网页与内置网页可以并存，尚未提供上传应用的入口。
- 旧多组实验界面、分组规范生成、调度器、评价与变化高亮接口已移除。`?view=experiments` 现在也显示卡片工作台；旧 `/api/experiments`、`/api/runs` 等接口返回 404。
- 磁盘中的历史实验和运行产物保留，不清理、不迁移其状态；旧实现可从 Git 历史恢复。
- `.data/`、`dist/` 与依赖不纳入 Git。数据目录使用进程锁，防止多个服务同时修改。

控制台写入接口校验来源和会话令牌；生成网页仅在另一个端口提供静态文件，并以限制权限的 iframe 运行。预览不能访问执行接口，文件读取拒绝路径穿越与符号链接。

网页验证允许通过 HTTPS 加载远程字体文件及字体样式表（如字体服务的 CSS），其他外部脚本、图片与业务请求仍受预览策略限制；生成期间获取并保存到交付目录的图片可正常预览。检查会等待字体加载并记录请求失败、字体错误或超时；加载成功不等于风格与业务适配已完成，也不能保证所有汉字都使用了预期字体。远程资源不可用时，浏览器可能显示回退字体。
