# Define Pretty

## 视觉特征卡片实验

当前实验分支 `experiment/visual-feature-cards` 将主流程改为：**上传参考图 → 查看带定位的特征卡片 → 编辑、勾选并组合 → 导出参考图片和配套指令**。尚未合并主分支，不预先假定这些卡片能够提升模型生成质量。

```sh
npm install
npm run dev:cards
# 或运行生产构建
npm run build:cards
npm run start:cards
```

打开 `http://127.0.0.1:4193`。实验数据独立保存在 `.data/visual-cards/`，构建输出在 `dist/visual-cards/`；旧实验台的默认端口 4173 与 `.data/` 历史不受影响。生成卡片复用本地 Codex 登录，可单独配置模型与推理强度；真实生成会消耗账号额度。

- AI 从截图发现可辨识的特征，不使用固定维度。每张卡片以一句话说明特征，正文依次为“带来什么效果”“怎么实现”“适合用在哪里”：帮助用户判断、指导模型实施、约束应用范围。调整条件并入实现规则；局部裁切、来源区域与可展开的图中依据用于核对。允许提供参考范围，明确区分观察估计与迁移建议，不把估计当作设计稿参数。
- 所有生成卡片默认不选中。可手动增删、调整文字、重新框选来源区域，并指定目标网页的应用位置；留空时由接收指令的模型按组件用途匹配。
- 手动添加后先框选区域，填写一句话特征，再点击「AI 补全」。沿用生成设置中的模型和推理强度，发送实际选区裁切图、整图上下文与用户意图，只补全图中依据、效果、实现规则和适用范围；标题、定位与用户选择保持不变。结果先填入草稿，点击保存才写回卡片。支持取消与刷新恢复；失败、超时或服务重启不改写原卡片。补全输入、结果和用量保存在独立的 `feature-completions/` 记录中。
- 导出前预览实际 PNG，只排入勾选卡片及对应编号引线，保留整张原图作为上下文。配套指令说明只借鉴所选特征，不复制业务内容。
- 选择和编辑自动保存；旧版卡片保留原文，其原实现要求与适配条件在展示、导出和编辑时合并到“怎么实现”，不自动补写内容。编辑保存后使用合并字段，历史测试输入仍保留原快照。重新生成新建记录，不覆盖原结果。可取消生成；服务重启将未完成任务标为中断，保留输入和日志。
- 卡片先提炼可迁移的设计关系，再用短句解释。图中实例、要保留的关系和可调整参数分别说明；允许常用设计词配合具体解释，避免退化为颜色与位置清单。输出前用不同业务、数量和可用空间检查规则。借鉴 STE 清晰写作原则，不宣称百分比合规；新生成记录保存 guidanceVersion。
- 图中定位与特征说明可能存在误判，需要人工核对。截图不能确认的数值、字体与不可见交互状态不会当作测量结果。

可把导出图片和配套指令交给现有 AI 编程工具，也可在当前页面点击「测试所选设计」。底部验证区域会并排展示原网页与 Codex 修改结果，支持同视口预览、全屏、取消及历史记录。

测试来源首次读取主实验台 `.data/store.json` 中最后创建实验的最新版本原始页，校验哈希后冻结到实验数据目录，不初始化或修改主实验台数据。需要其他主数据目录时可设置 `DEFINE_PRETTY_SOURCE_DATA_DIR`。测试模型默认沿用来源实验，可在验证区独立调整。每次从相同基线副本开始，发送当前选中卡片的实际导出 PNG 和配套指令；保存图片哈希、卡片版本、完整提示词与模型配置。CLI 仅在该次 `work/website/` 副本内修改网页，历史输入保存在工作目录之外。生成完成后检查网页加载与资源错误，保留失败原因和可预览产物，不计算美观分数。测试最长 30 分钟，可取消；刷新恢复记录，重启将未完成任务标为中断。原对比实验界面仍保留在 `?view=experiments`；“实验台历史”链接进入旧端口。

## 原对比实验工具

以下为原实验台的使用说明，旧 API 与数据格式保留。

## 启动

需要 Node.js 22.12+、已安装并登录的 Codex CLI，以及用于检查生成网页的 Chrome、Edge 或 Playwright Chromium。

```sh
npm install
codex login status
npm run dev
```

打开终端输出的本地地址，默认是 `http://127.0.0.1:4173`。控制台与 API 在 4173 端口，生成页面只读预览在 4174 端口；两个服务只监听本机。

可通过 `DEFINE_PRETTY_PORT`、`DEFINE_PRETTY_PREVIEW_PORT` 和 `DEFINE_PRETTY_DATA_DIR` 指定端口与数据目录。同一数据目录只允许一个服务实例，重复启动会直接退出，避免误改正在运行的任务状态。

```sh
npm run check
npm test
npm run build
npm start
```

运行检查自动寻找本机浏览器。找不到时可以设置 `DEFINE_PRETTY_CHROME` 为浏览器可执行文件绝对路径，或运行 `npx playwright install chromium`。无法运行浏览器检查的记录会显示失败，不会伪装为通过。

## 做一轮实验

1. 创建实验，确认业务需求和运行模型。默认业务是中文项目管理 Dashboard。
2. 上传**纯 UI 截图**，配置规范生成模型与推理强度，点击「根据参考图生成规范」。预览结果后追加或替换为可编辑维度，也可手动新增维度或添加九组示例模板。生成提示词也可编辑；换图不会自动替换规范。
3. 保存配置，生成原始页面。原始组只收到业务需求与统一的静态网页交付、功能检查约束，不会收到参考图或任何设计规范。
4. 原始页面通过检查后，运行单维度组并查看效果。在对比画布的结果卡片上勾选至少两个维度，点击「组合并生成对比」新增组合组。也可运行全部修改组。
5. 在对比页查看页面；在运行详情中查看真实输入、网页预览，并记录人工评价。每个实验组卡片和详情预览的右下角均有全屏按钮，可在当前浏览器内放大查看；没有网页产物时按钮禁用。

原始页生成、修改组执行和重跑都调用真实 `codex exec`，消耗当前 Codex 账号的额度。上传图片会作为所选修改任务的模型输入发送。没有上传图片时可以先生成原始页，不能执行修改组。

## 自选维度如何比较

- **原始对照组**：只根据业务需求正常生成页面。
- **直接参考图组**：同一基线副本 + 参考图，只发送一句「website/ 中已有一份完整的项目管理网页。请参照所附参考图的风格润色这个网页。」不追加业务保留、测试标记或交付约束。
- **参考图+文字规范组**：同一基线副本 + 同一参考图 + 当前已保存版本的全部维度规范；与前两组固定在总览第一排。生成的规范需先采纳并保存，人工编辑后的内容以保存版本为准。
- **单维度组**：每个自定义维度自动成为一组，只收到该维度的规范和修改范围。
- **组合组**：同一基线副本 + 同一参考图 + 所选维度规范。以选中维度为目标，协调相互冲突的规则，允许为可读性、布局完整和交互做必要适配。

新版规范把「整页视觉重点」作为唯一的独立维度，负责整页视觉中心、主次区域比例和阅读顺序。其余维度各含 3–5 条自身属性的核心规则，不继承或重新定义整页重点。单维度与组合只发送选中的文字；C2 发送全部维度原文，不再另生成整体执行稿。历史规范不会自动重写，切换新版需重新生成、采纳并保存新版本。

单维度卡片支持编号式重点标注：使用规范生成模型分析实际规范、前后首屏和组件位置，只标注与当前维度有关的变化，结果缓存。高亮在每个 5 秒周期内渐显 0.4 秒、保持 2.2 秒、渐隐 0.4 秒，再隐藏 2 秒；前后说明可展开。

维度名称、数量、修改范围与提示词都可编辑。示例模板包括布局、间距、字体等九章，使用时可删除或替换。组件章节会涉及多种视觉属性，不代表完全独立的统计因素。规范组要求保留业务内容、数据和交互功能；直接参考图组使用上述日常简短指令。

每个修改任务都从冻结的原始页开始，而不是接着上一组修改。每次运行使用新目录和新会话。并行数量可在运行配置中输入任意正整数，默认 2；保存新版本后，该版本的任务按此上限调度，不同版本分别计数。只改并行数量仍可复用原始页，不影响旧版本正在执行的任务。单任务超时 30 分钟。失败不会自动重试或自动进行额外审美修正。

## 版本、检查与评价

保存修改会产生新版本；重跑会产生新记录。只改图片、规范、组合组或规范生成配置时可复用符合相同业务与运行配置的已冻结基线。修改业务需求或对照实验模型配置会要求新基线。每条修改记录保存其实际使用的基线 ID 和哈希，后续生成的新基线不会改变旧结果。

浏览器检查包括入口、资源、脚本、任务标识、搜索、筛选及详情操作。修改组还对照基线记录任务数据与可见文本变化。检查能发现功能问题，但不保证模型只改了指定设计维度。直接参考图组仍执行同样的事后检查；若改动了测试标记或内容，保留检查失败与网页产物，不向模型补发约束或自动修正。

人工评价分开记录“规范遵循”“范围外变化”“审美偏好”，附备注。工具不计算自动美观总分，也不把中文受控表达称为 STE 认证。

服务重启后，未完成任务标记为中断，保留日志，由用户决定是否重跑。取消会终止当前任务的进程组。

## 本地数据与执行边界

所有配置、参考图、输入快照、产物、检查和评价保存在 `.data/`，已加入 `.gitignore`。备份时停止服务并复制该目录。控制台不会保存或展示 Codex 登录凭据；CLI 复用现有本机登录及 provider 配置。

生成网页是静态 HTML/CSS/JavaScript，不安装各自的依赖、不使用远程资源。预览服务与执行 API 分离，预览使用受限 iframe 和 CSP。CLI 工作目录按任务分开，提示词限定其修改范围；这不是容器级文件系统隔离。

首轮只应得出当前参考图、业务页面和模型配置下的观察结果。需要判断稳定性时，再保留历史重复运行。

## 规范生成记录

规范生成与对照实验独立配置模型和推理强度，复用本地 provider 和登录。生成使用新的只读 Codex 会话、图片附件和 JSON Schema 输出；不提供原始网页或其他组规范。截图无法精确确认的数值要求标为估计，不推断不可见交互状态为事实。结果先预览再采纳，不会自动改变已保存实验版本。

生成记录与原始 JSONL、输出、图片副本、提示词和用量保存在 `.data/generations/` 及本地记录中，可在页面回看。一次运行一个规范生成任务，可取消；30 分钟超时、CLI 失败或格式校验失败都保留记录。服务重启将未完成的规范生成标为中断，不自动补跑。维度来源记录会随采纳结果保留。

维度最多 100 个，组合组最多 100 个，每个组合至少引用两个不同的现有维度。在设置中删除维度时，草稿里引用该维度的组合一并移除，已保存版本保持不变。

组合组在观察结果后追加到当前版本，不修改已有组、规范、运行或评价。所选结果必须是当前版本、同一冻结基线的单维度结果，且运行已结束并有网页预览；检查失败但有产物的结果也可选。组合记录保存所选运行 ID 与维度顺序。追加组合与创建首次运行原子保存，既有卡片留在当前画布；随后按版本并行配置调度。
